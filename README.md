Security Researcher focused on two complementary areas: <strong>Web3 protocol security</strong> and <strong>Web2 application security</strong>.

In Web3, my research covers smart contracts, DeFi systems, cross chain protocols, blockchain infrastructure, consensus, governance, staking, oracle integrations, token accounting, share pricing, liquidation logic, bridge and message validation, replay protection, authorization boundaries, state transitions, economic invariants, reserve accounting and protocol liveness.

In Web2, my work covers web applications, APIs, backend services, authentication, authorization, multitenancy, access control, attacker controlled input, logging, telemetry, parsers, serialization and security sensitive integrations.

My research methodology is centered on reproducibility. Findings are developed through real protocol or application paths whenever possible, with explicit control cases, measurable state transitions, bounded impact claims, public evidence when disclosure is permitted and remediation oriented reporting.

<details open>
<summary><strong>ZIGChain · Native Wrapper Reserve Drain</strong></summary>

<p>
  <img src="https://img.shields.io/badge/Final-Critical-b91c1c?style=flat-square" alt="Critical">
  <img src="https://img.shields.io/badge/Reward-%24443.00-0A66C2?style=flat-square" alt="443 USD reward">
  <img src="https://img.shields.io/badge/Channel-HackenProof_Audit-7c3aed?style=flat-square" alt="HackenProof Audit">
</p>

<strong>Finding:</strong> Base denom only validation allowed untrusted IBC vouchers to collide with the native token identity and drain native token wrapper reserves.

<strong>Security themes:</strong> cross chain trust boundaries, token identity, reserve accounting and wrapper invariants.

<strong>Evidence:</strong> <a href="https://dev.to/f00dat/how-a-base-denom-collision-let-untrusted-ibc-vouchers-drain-zigchains-native-reserves-3o5j">Technical article</a> · <a href="https://hackenproof.com/reports/ZIGCHDD-74">Public report</a>

</details>

<details open>
<summary><strong>Overlayer · Permanently Stranded First Inbound Transfers</strong></summary>

<p>
  <img src="https://img.shields.io/badge/Final-Critical-b91c1c?style=flat-square" alt="Critical">
  <img src="https://img.shields.io/badge/Reward-%2468.97-0A66C2?style=flat-square" alt="68.97 USD reward">
  <img src="https://img.shields.io/badge/Channel-HackenProof_Audit-7c3aed?style=flat-square" alt="HackenProof Audit">
</p>

<strong>Finding:</strong> Destination local `totalBridgedOut` accounting underflowed on the first inbound transfer and could permanently strand cross chain funds.

<strong>Security themes:</strong> distributed accounting, bridge invariants, state initialization and cross chain liveness.

<strong>Evidence:</strong> <a href="https://dev.to/f00dat/how-overlayers-destination-local-counter-permanently-stranded-first-inbound-transfers-7i7">Technical article</a> · <a href="https://hackenproof.com/reports/OVLRSCDD-30">Public report</a>

<details open>
<summary><strong>TipRun · Unsigned Deleverage Economic Terms</strong></summary>

<p>
  <img src="https://img.shields.io/badge/Submitted-High-e67e22?style=flat-square" alt="Submitted High">
  <img src="https://img.shields.io/badge/Final-Critical-b91c1c?style=flat-square" alt="Final Critical">

<strong>Security themes:</strong> authorization, signed intent, collateral custody, settlement boundaries and business logic.

<strong>Evidence:</strong> <a href="https://dev.to/f00dat/how-tipruns-unsigned-deleverage-path-allowed-arbitrary-collateral-transfers-edg">Technical article</a>

<details open>
<summary><strong>TipRun · Liquidation of Healthy Accounts</strong></summary>

<p>
  <img src="https://img.shields.io/badge/Submitted-High-e67e22?style=flat-square" alt="Submitted High">
  <img src="https://img.shields.io/badge/Final-Critical-b91c1c?style=flat-square" alt="Final Critical">

<strong>Finding:</strong> `TYPE_LIQUIDATE` applied liquidator signed terms to healthy accounts without liquidation eligibility checks or oracle price bounds.

<strong>Security themes:</strong> liquidation eligibility, oracle constraints, signed terms and collateral safety.

<strong>Evidence:</strong> <a href="https://dev.to/f00dat/how-tipruns-liquidation-path-could-force-healthy-accounts-into-arbitrary-terms-3n3m">Technical article</a>

<details open>
<summary><strong>Fluid DEX V2 · Withdrawal Above Position Balance</strong></summary>

<p>
  <img src="https://img.shields.io/badge/Final-High-e67e22?style=flat-square" alt="High">
  <img src="https://img.shields.io/badge/Reward-%2434.00-0A66C2?style=flat-square" alt="34 USD reward">
  <img src="https://img.shields.io/badge/Channel-Sherlock-111827?style=flat-square" alt="Sherlock">

<strong>Finding:</strong> A normal supply withdrawal capped the MoneyMarket storage debit while forwarding the uncapped requested amount to pooled Liquidity, enabling withdrawal above the recorded position balance.

<strong>Security themes:</strong> shared liquidity, accounting invariants, withdrawal validation and state synchronization.

<strong>Evidence:</strong> <a href="https://dev.to/f00dat/how-a-1-usdc-position-let-an-attacker-withdraw-800-usdc-from-fluid-moneymarkets-shared-liquidity-4pcn">Technical article</a> · <a href="https://audits.sherlock.xyz/contests/1225/voting/860">Sherlock submission</a>
